# reference_parser — 참고용 스냅샷

친구가 **프로젝트 때 참고용으로 쓰라고** 만들어 올려두는 코드다.
Windows 아티팩트를 LLM 없이 결정론적으로 파싱하는 계층을 통째로
떼어낸 스냅샷이고, "이런 식으로 짜면 된다" 를 보라고 둔 것이다.

## 그대로 돌아가지는 않는다 (의도된 것)

원래 파이프라인(`src/stage04_parse/`) 에서 떼어온 거라
상대 임포트가 바깥을 가리킨다 — `..common.io`, `...common.refs`,
`third_party.analyzeMFT`, 그리고 룰 원본인 `mappings/_artifacts.yaml` /
`mappings/_flags.yaml`. 이 폴더만으로는 import 가 안 된다.

**실행 대상이 아니라 읽는 대상이다.** 필요한 부분만 골라서
자기 구조에 맞게 옮겨 쓰면 된다.

## 구성

| 파일 | 역할 |
|---|---|
| `evidence.py` | 증거 접근 계층. "아티팩트 이름 → 바이트 스트림" 하나로 접점을 좁혀서, 파서가 추출 파일/dd 이미지/E01 중 뭔지 몰라도 되게 한다. 한 실행 = 한 볼륨 원칙 |
| `parse.py` | 04단계 엔트리포인트. 선별 결과를 받아 지정된 범위만 읽고, 파서/증거가 없으면 조용히 빈 결과를 내지 않고 `errors.jsonl` + `_manifest.json.skipped` 에 남긴다 |
| `flagging.py` | `flags` 어휘 룰을 한 곳에서 일괄 적용. 어휘가 파서마다 흩어지지 않게 YAML 하나를 원본으로 둔다 |
| `parsers/` | 아티팩트별 파서 — `mft`, `usnjrnl`, `evtx`, `registry`, `prefetch`. 등록 목록은 `parsers/__init__.py` |
| `structs/` | 바이너리 레코드 구조체 — MFT 레코드, prefetch 레코드, USN 레코드, XPress Huffman 압축 해제 |

## 볼 만한 부분

- **파싱에 LLM 을 안 쓴다.** 데이터 계층에서 환각이 나면 그 뒤 검증이
  통째로 불가능해진다. 그래서 04단계는 전부 결정론이다.
- **아티팩트 ≠ 파일 하나.** `prefetch` 는 폴더 안 `.pf` 전부가 아티팩트
  하나이고, `evidence.open_all` 이 파일마다 파서를 부른다. 파서는 자기가
  몇 번째로 불렸는지 몰라도 된다.
- **아티팩트를 이름이 아니라 경로로 찾는다.** `SYSTEM` 같은 흔한 파일명이
  사용자 다운로드 폴더의 동명 파일에 선점당하지 않게, 볼륨 안의 제자리를
  먼저 본다.
- **시간 범위는 기본이 소프트 필터.** `outside_time_range` 만 붙이고 다
  내보내되, 파일이 크면(기본 100MB) 하드 컷으로 바꾼다.

각 파일 맨 위 docstring 에 "왜 이렇게 했는지" 가 다 적혀 있으니
거기부터 읽는 걸 권한다.
